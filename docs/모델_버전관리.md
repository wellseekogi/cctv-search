작성자 PC의 위치는 `C:\컴퓨터비전\cctv-search`입니다. 2026-11-05에 GitHub 인증을 마치고 공개 원격 [wellseekogi/cctv-search](https://github.com/wellseekogi/cctv-search)를 연결했습니다. 브랜치 3개와 기준선·SigLIP2 태그를 공유합니다. 새 팀원은 README의 팀원용 시작 절차를 사용합니다.

미커밋 변경이 있으면 먼저 확인하고 커밋한 뒤 전환합니다. models·runs·가상환경은 브랜치를 전환해도 로컬에 남습니다. 서로 다른 모델의 vectors를 섞지 않습니다.

## 설정으로 비교하기

현재 브랜치에는 다음 설정이 있습니다.

- `configs/embedding.clip.yaml`: 기존 CLIP ViT-B/32, 512차원, GPU 배치 16/CPU 4.
- `configs/embedding.siglip2.yaml`: SigLIP2 Base Patch16 224, 768차원, GPU 배치 4/CPU 2, precision=auto.
- `configs/embedding.siglip2.fp32.yaml`: 같은 SigLIP2를 FP32로 계산, GPU 배치 2/CPU 2.
- `configs/embedding.yaml`: 현재 브랜치의 기본값, SigLIP2 auto 설정과 동일.

auto 정밀도는 CUDA=FP16, CPU=FP32입니다. 저장 벡터는 항상 float32로 L2 정규화합니다. 모델 ID·리비전·가중치 SHA256·차원은 함께 맞춰야 합니다. 현재 구현은 공식 SigLIP2 FixRes 모델용이며 NaFlex는 지원하지 않습니다.

```powershell
.\.venv-siglip2\Scripts\python.exe -m tools.verify_embedding --config configs/embedding.clip.yaml --output runs/compare-clip-01
.\.venv-siglip2\Scripts\python.exe -m tools.verify_embedding --config configs/embedding.siglip2.yaml --output runs/compare-siglip2-01
.\.venv-siglip2\Scripts\python.exe -m tools.verify_embedding --config configs/embedding.siglip2.fp32.yaml --output runs/compare-siglip2-fp32-01
```

CPU를 명시하려면 `--device cpu`를 추가합니다. 출력 디렉터리는 새 이름을 사용합니다. 모든 검증은 같은 합성 이미지와 samples를 사용하며, 실행의 requested_config·설정 해시·Git 커밋·미커밋 변경 여부·모델/전처리 식별·실측 버전을 verification_report.json에 남깁니다. pipeline은 items·vectors·오류·배치 기록을 따로 저장합니다.

기존 CLIP 브랜치의 검증 도구는 `--config` 옵션이 없으며 `python -m tools.verify_embedding --output runs/clip-baseline-01`로 실행합니다. 두 모델을 비교할 때는 feature/siglip2 브랜치에서 위 명령을 사용하면 됩니다.

## 변수 하나를 바꿀 때

모델 비교 중에는 samples·이미지·질의를 동일하게 유지합니다. 새 YAML을 복사해 여백, 배치, 정밀도, 해상도별 체크포인트 등을 한 번에 한 항목씩 바꾸고 설정을 커밋한 다음 실행합니다.

```powershell
git switch -c experiment/siglip2-margin-15
Copy-Item configs/embedding.siglip2.yaml configs/embedding.siglip2.margin15.yaml
# 복사한 YAML의 crop_margin_ratio를 0.15로 수정
git add configs/embedding.siglip2.margin15.yaml
git commit -m "exp: compare SigLIP2 crop margin 0.15"
.\.venv-siglip2\Scripts\python.exe -m tools.verify_embedding --config configs/embedding.siglip2.margin15.yaml --output runs/siglip2-margin15-01
```

실제 검색 성능 비교에서는 F의 고정 dev 질의·정답으로 Recall@5/10과 MRR을 측정해야 합니다. 현재 도구의 두 장짜리 합성 색상 질의는 작동 확인용이며 모델 선정 근거가 되는 CCTV 벤치마크는 아닙니다. 이미지 해상도는 체크포인트의 공식 전처리를 따릅니다.

## 로컬 모델

SigLIP2는 다음 경로에 있습니다.

`models/siglip2-base-224/75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2/model.safetensors`

가중치 크기는 1,500,800,904바이트, SHA256은 `612923381c76ec5a9bed335d1c48827e3f2e506ac31b044b63b2031fadee6a0b`입니다. 모델 리비전은 `75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2`로 고정했습니다. 이미지 전처리와 tokenizer 파일도 같은 리비전에서 받습니다. 로컬 파일이 있으면 다운로드 없이 로드하고 매번 가중치 SHA256을 확인합니다. 손상된 가중치는 자동으로 신뢰하지 않고 오류를 냅니다.

CLIP은 기존 `models/ViT-B-32.pt`를 사용합니다. Git에는 models, .venv 계열, 캐시, runs, .env와 가중치 확장자를 제외했습니다. 소스 ZIP도 모델을 포함하지 않습니다. 공식 다운로드 출처는 [Google 모델 저장소](https://huggingface.co/google/siglip2-base-patch16-224/tree/75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2)입니다.

SigLIP2는 학습 규칙에 따라 소문자 처리·64토큰 padding을 적용합니다. 길이를 넘기면 TEXT_TOO_LONG 예외로 반환하며, 질문을 임의로 자르지 않습니다. 한국어 토큰 수는 CLIP의 tokenizer와 다릅니다. 긴 문맥 처리와 시간 순서 추론은 모델을 바꾸는 것만으로 구현되지 않습니다.

## 2026년 11월 4일 검증

Python 3.11 CPU 자동검사 42개가 통과했습니다. 기준선의 32개에 설정 선택·모델 차원·가중치 손상·리비전 고정·64/65토큰 경계·소문자 처리 등의 10개를 추가했습니다. 로그는 `docs/verification/unit-tests-siglip2-python311.txt`입니다.

실제 모델 검증 실행은 다음과 같습니다.

- `runs/siglip2-verified-gpu-20261104`: Python 3.13.5, CUDA FP16, 실제 모델 검사 5개 PASS.
- `runs/siglip2-verified-cpu-20261104`: Python 3.11.15, CPU FP32, 실제 모델 검사 5개 PASS.
- `runs/clip-config-check-20261104`: 새 설정 선택 경로에서 CLIP 재실행, 실제 모델 검사 5개 PASS.
- `runs/siglip2-fp32-cli-20261104`: FP32 설정으로 실제 CLI build·validate 실행.

SigLIP2는 items 4행·vectors `[4,768]`, 빈 입력 `[0,768]`, warm 벡터 캐시 4/4 hit를 확인했습니다. 최대 정규화 오차는 GPU 약 `1.79e-7`, CPU `0.0`으로 허용값 0.0001 이하였습니다. 영어·한국어 질의도 `[4,768]`로 인코딩했습니다. SigLIP2의 예제 질의 토큰 수는 각각 7·7·10·9였습니다.

FP16에서는 배치 크기에 따라 같은 이미지 좌표 최대 차이가 약 0.000194 발생했으며, 코사인 유사도는 약 0.9999992였습니다. 기존 좌표별 allclose 검사를 동일 이미지의 코사인 0.99999 이상 검사로 바꾸고 좌표 최대 차이를 함께 기록했습니다. 이는 검색에서 사용하는 벡터 방향의 일관성 검사이며, 유한값·float32·L2 정규화 오차 0.0001 검사는 그대로 유지했습니다. CPU FP32의 같은 이미지 좌표 차이는 0.0이었습니다.

이 합성 예제에서 GPU FP16의 PyTorch peak allocated는 792,429,056바이트였습니다. 전체 GPU 사용량이나 다른 프로그램과 함께 돌릴 때의 상한은 아니며, 실제 영상의 배치 성능은 별도로 측정해야 합니다.

## 이력을 포함한 전달 파일

`git-history.bundle`에는 기준선·새 브랜치·태그의 Git 이력을 저장할 수 있습니다. 가중치는 포함되지 않습니다. 소스 ZIP에 이 bundle과 검증 결과를 함께 넣습니다.

```powershell
git bundle create git-history.bundle --all
git bundle verify git-history.bundle
# ZIP을 푼 폴더에서 새 저장소로 복원
git clone -b feature/siglip2 git-history.bundle cctv-search-restored
```

실제 A samples·B 디코더·원본 CCTV는 아직 제공되지 않아 통합 및 실제 검색 성능 비교는 미검증입니다. 다른 팀원의 인수 실행도 필요합니다. 공개 저장소는 인증 없이 복제할 수 있으며, 변경사항 업로드에는 저장소 쓰기 권한과 GitHub 인증이 필요합니다.
