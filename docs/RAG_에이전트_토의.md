# 로컬 프레임 추천 기능의 에이전트 검토

사용자의 최종 요구는 질문을 임베딩하고 저장된 벡터에서 유사한 항목을 찾아, 프레임 번호와 시각을 여러 개 추천하는 것입니다. 검색된 장면의 내용을 새로 판독하거나 영상 전체의 행동을 설명하는 기능은 이번 범위에 포함하지 않습니다.

## 검토와 합의

세 에이전트가 모델 선정, D 연결 구조, 답변 근거를 나눠 검토하고 서로 의견을 교환했습니다.

- 모델 선정 담당은 현재 4GB GPU와 SigLIP2의 동시 사용을 고려했습니다. 프레임 추천 메타데이터를 안내하는 데에는 VLM이 필요하지 않으며, 작은 텍스트 모델을 CPU에서 사용하는 구성을 제안했습니다.
- 연결 구조 담당은 D가 다른 PC에서 호출할 수 있도록 함수 하나가 로컬 HTTP 서비스에 요청하는 구조를 제안했습니다. 인덱스와 임베딩 모델은 서버에서 한 번 준비하고 재사용합니다.
- 근거 검토 담당은 유사도가 장면의 존재나 행동을 확정하는 증거가 아님을 확인했습니다. 프레임·시각·점수는 저장된 인덱스에서 코드가 복원하고, 생성 모델이 이를 수정하지 못하도록 하는 데 합의했습니다.

처음에는 이미지 내용을 답하는 VLM도 검토했지만, 사용자가 프레임·초 추천이면 충분하다고 명확히 해 해당 추가 기능과 다운로드를 제외했습니다.

## 선정 모델과 자원 기준

선정 후보는 공식 Qwen3-0.6B의 Q8_0 GGUF입니다. 가중치는 약 639MB이며 CPU 생성으로 시작합니다. 런타임은 llama.cpp의 로컬 서버, 초기 context는 2048토큰, 최대 생성 길이는 128토큰으로 제한합니다. 이는 이 기능의 초기 실행 설정이며, 모델 전체가 지원하는 문맥 길이를 의미하지 않습니다.

Qwen3-0.6B의 역할은 유사 후보를 안내하는 한국어 소개문 선택입니다. 자유로운 내용 생성 대신 JSON schema로 정해진 안전 안내문 세 개 중 하나를 고르게 하고, 엔진도 허용 문장인지 다시 검사합니다. 질문의 새 사실을 재진술하거나 새로운 시각을 쓰게 하지 않습니다. 수치와 목록의 작성자는 생성 모델이 아니라 서버 코드입니다. GPU는 현재 SigLIP2 이미지·텍스트 임베딩에 사용할 수 있게 남깁니다. 모델 크기와 실제 메모리·처리시간은 구분하며, 최종 실행 결과에서 해당 PC의 측정값을 확인합니다.

모델과 런타임의 실제 고정 리비전·다운로드 파일·해시는 최종 설정 및 다운로드 검증 기록을 기준으로 합니다. 모델 가중치와 로컬 API key는 공개 Git 저장소에 넣지 않습니다.

## D가 받는 기능의 의미

D는 `recommend_frames` 함수 하나를 호출해 질문과 선택 필터를 전달합니다. 결과에는 한국어 안내문과 recommendations 배열이 들어갑니다. D가 다른 PC에서 사용한다면 해당 함수는 사용자 PC의 서비스 주소에 요청합니다. 사용자 PC에서 모델 서비스가 실행 중이어야 합니다.

각 추천의 item_id·video_id·frame_index·실제 시각·점수·표현·bbox는 검증된 items와 vectors에서 가져옵니다. frame_index는 기존 계약대로 0부터 시작합니다. 원본 시각의 초는 actual_timestamp_ms / 1000이며, 일부를 잘라 저장한 파일의 재생 위치는 actual_timestamp_ms - source_offset_ms로 구분합니다.

같은 영상·프레임·실제 시각의 scene과 object가 함께 검색되면 최고 점수의 대표 항목 한 개만 남깁니다. 동점은 영상 ID·프레임 번호·item_id 순으로 고정합니다. 이로써 같은 프레임의 scene·crop이 추천 목록을 중복 점유하지 않게 합니다.

## 생성 모델의 경계

허용하는 안내는 SAFE_SUMMARIES에 등록한 “질문과 임베딩 유사도가 높은 프레임 후보입니다” 등의 세 문장뿐입니다. “실제로 빨간 차가 있다”, “해당 영상 전체에 없다”, “정지한 뒤 우회전했다” 같은 새 관찰이나 시간 순서 판단은 생성하지 않습니다. 현재 기능을 일반적인 자유형 RAG 질의응답 모델로 설명하지 않습니다.

생성 모델은 프레임 번호·초·순위를 작성하지 않습니다. 서버가 계산한 recommendations와 코드로 렌더링한 목록이 기준입니다. 소개문에 임의 시각이나 확정적 관찰을 넣는 출력은 사용하지 않고 정형 소개문으로 대체합니다. 모델 실패·시간 초과가 있어도 검색 결과 자체는 반환할 수 있어야 합니다.

빈 인덱스나 명시적인 빈 영상 필터는 정상적인 빈 결과입니다. 낮은 유사도만으로 실제 장면이 없다고 판정하지 않습니다. 점수는 정규화 벡터의 내적이며, 정답 확률이나 정확도 백분율이 아닙니다.

질문의 생성 모델 context와 검색 인코더의 입력 한계는 별개입니다. 현재 SigLIP2 검색 인코더는 특수 토큰을 포함해 64토큰까지 처리하며, 넘으면 명시적인 TEXT_TOO_LONG 오류를 반환합니다. 질문을 조용히 잘라 조건을 잃은 상태로 검색하지 않습니다.

## 수용 검사

- 손계산 가능한 고정 벡터에서 내적 점수·순위·동점 순서를 대조합니다.
- scene/object가 같은 프레임일 때 중복을 제거한 뒤 top_k를 적용하는지 확인합니다.
- source_offset이 있는 예제로 원본 시각과 파일 재생 위치를 구분합니다.
- 빈 인덱스·빈 필터·알 수 없는 영상 ID와 잘못된 입력을 구분합니다.
- 64토큰 경계와 65토큰 초과를 검사하고, 초과 요청에서 임베딩을 실행하지 않는지 확인합니다.
- 생성 모델이 실패하거나 잘못된 시간·명령을 출력해도 추천 배열이 바뀌지 않는지 확인합니다.
- 인덱스 해시와 질의 인코더의 모델·전처리 식별이 맞지 않으면 답변 전에 거부합니다.

이 검사들은 검색·연동 계약의 확인입니다. 실제 CCTV 검색 Recall·MRR이나 다양한 상세 질문의 품질을 증명하는 벤치마크는 아니며, 해당 평가는 F의 실제 영상·질의·정답이 준비되면 별도로 수행해야 합니다.
